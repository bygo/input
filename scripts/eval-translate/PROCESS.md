# 美国经济 100 句 × i18n 本地翻译审计过程

## 范围

- **原文**：`sentences.json`（100 句英文，美国经济分析）
- **目标语言**：应用设置里全部 12 种  
  英语 / 中文 / 日语 / 韩语 / 法语 / 德语 / 西班牙语 / 葡萄牙语 / 意大利语 / 俄语 / 阿拉伯语 / 越南语
- **模型**：仅本地 `qwen2.5:3b`（Ollama），**不用云端**
- **路径**：对齐 app 的「选中翻译」`select_prompt` + JSON schema 输出
- **审计**：脚本纯度（汉字/假名/韩文/西里尔/阿语/拉丁）、英文实词残留、空 `{}`

## 过程

### 1. 试点 v1（10 句 × 12 语 = 120）

- 总通过率 **92.5%**（111/120）
- 中文/英语/西欧语种基本满分
- 主要失败：
  - **阿拉伯语 60%**：英文残留（`central bank` / `Recession`），甚至夹中文
  - **韩语**：`Core inflation` / `Recession` 未译
  - **日语**：`Groceries` / `households`
  - **俄语**：`thirds`；另有漏检的中俄夹杂

### 2. Prompt + 过滤修复

改动（已进 app）：

1. `select_prompt` 按语言加正例/反例（禁 overnight 式夹杂）
2. `user_message` 显式带「目标语言：X，禁止夹杂」
3. `lang::fits_target` 覆盖日/韩/俄/阿/越及西欧语（混脚本直接丢弃）
4. 本地不合格时 **repair 再试一次**，再不行才云端 fallback（评测脚本同样做 repair，但不走云端）

### 3. 试点 v2 / 难语言 v3

- 审计变严后总通过率短暂降到 ~90%（把以前漏掉的中俄夹杂抓出来了）
- repair 后难语言：日语 **10/10**，俄语 **8/10**，阿语 **7/10**，韩语 **8/10**

### 4. 全量 100 × 12 — **已暂停**

跑到约 440/1200 时失败模式已稳定复现，继续刷数意义不大，已手动停掉。

重复失败类型：

| 类型 | 典型语言 | 例子 |
|------|----------|------|
| 英文实词残留 | 韩/日/俄/德/阿/中 | `overnight` `Layoffs` `Core` `affordability` `thirds` |
| 目标语里夹中文 | 俄/阿/越/德 | 俄语夹「挤压于房租」；阿语夹「降低了」 |
| 专有名词未处理 | 多语 | `CHIPS` `Federal Reserve` 原样粘贴 |
| 空/乱码 | 偶发 | 德语 `...` |

## 结论

1. **qwen2.5:3b 本地翻译上限就在这**：中文/英语/法西葡意还行；阿语/俄语/韩日财经词经常中英（或中阿/中俄）夹杂。
2. **Prompt + repair 有用但不够**：试点从「阿语 60%」抬到约 70%，日语难集可到 10/10，但全量里失败仍密。
3. **App 侧已落地的防护**（比继续盲跑全量更重要）：
   - 多语言 `select_prompt` 正/反例
   - `user_message` 带目标语言约束
   - `fits_target` 拒混脚本 → 触发云端 fallback
   - 本地失败先 repair 一次再 fallback
4. 不必为了报表把 1200 条跑完；要复测时用试点即可。

```bash
cd scripts/eval-translate
python3 eval_local.py --limit 10 --out report-pilot.json
python3 eval_local.py --limit 10 --langs '日语,韩语,俄语,阿拉伯语' --out report-hard.json
```
